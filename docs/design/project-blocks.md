# Shared project summaries and task rows

Implementation of [B1–B4](shared-blocks.md), [K-A1–K-A8](task-counters.md) and Menu M2/M3, under R6. TaskQ owns `src/project-blocks.js` and `.css`; the tray and standalone browser bundles use this same source. No network client, credentials, parser, framework or task operation is added.

The [selected app foundation](app-foundation.md) applies to TaskQ shells, not these exported assets. A Preact shell consumes the existing API through an isolated DOM island; only the island owns its descendants. No framework enters the released project-blocks bundle.

## Interface and delivery

`TaskqProjectBlocks` (browser global or CommonJS) exposes `summary(project)`, `aggregate(all)`, `counters(counts,…)`, `task(project,row,global,compact)`, `handle(event,adapter)` and `marks` (icon and tone per state id). Insert returned HTML; bind the click handler once. Adapter functions `project(id)`, `tasks(id,state)` and `open(url)` own navigation. Project and counter controls are siblings, never nested. Consumers arrange blocks and set the inherited font/available width; they do not override internals.

A project has `{id,name,board:{kind,url},counts,partial,tasks}`. `counts` (`[{state,name,n}]` in strip order, `n` null when unknown), `partial` and `open` come from the Rust display model (`src/display.rs`); the component renders them and keeps no count, order, name or age rule. Board URL identifies provider/server/repository; `id` only routes navigation. Rows are canonical snapshot rows (`n`, `state`, `revision`, `title`, `url`) plus the model's `state_name` and `age` text and adapter-supplied `host`, `runtime`, `local_session`, `session_url`. Claude session links are account-scoped HTTPS URLs and show on every host; `codex://threads/` links show only on the owning host (`local_session`), elsewhere the row shows `session_reason`. A remote row shows a remote mark before the runtime mark, no remote text. Links accept HTTP(S), with `codex://threads/` additionally allowed for local sessions. Untrusted text is escaped.

The model deduplicates board/issue identities, keeps Doing and Review distinct, keeps unknown unknown and marks stale/incomplete/conflicting sources Partial; counters hide known zero. `summary(project,selected,open)` and `aggregate(all,selected)` optionally take a state array for the tray filter strip: show icon-only zeros, mark capsules with `aria-pressed` and include All tasks. Its count is the deduplicated open-row total across all projects, Held included and closed rows excluded; the project adapter supplies the selected project/search `open` count (MP11/O2). Omit the array for ordinary nonzero project summaries. The tray owns OR toggles and All tasks navigation; the component writes no queue state. Held counts open `held` rows; there is no Closed counter (#1476). The tray adapter adds Start for held drafts; the component itself stays operation-free. The native adapter's filter route shows the matching observed project/state rows; partial data remains labelled.

Release staging publishes `taskq-<release>-project-blocks.js`, `.css`, `.LICENSE`, `-fixtures.json` and `-sources.json` through the existing release workflow, checksums and attestations. DashQ pins an actual release and its checksums, serves assets locally under its CSP, and supplies its own navigation adapter. Source hashes are not evidence of release publication or DashQ adoption. No DashQ files are edited here.
