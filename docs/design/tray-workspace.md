## Contract detail

The Conversations window renders the v7 look recorded in [visual style](visual-style.md) (#1773). Workspace navigation state stays within its storage bound, so an oversized saved view is trimmed (oldest opened threads first) instead of showing an invalid-navigation banner.

- TW1 Navigation (point 1; V01–V06): every screen has one fixed header: a first row of Home, the route title when it fits, trailing actions, then the separate window-control group; Back, breadcrumbs and a title that does not fit take the row below (MP12, #1660). No content title. Roots: tray Home and workspace Conversations (one thread screen; no Inbox section, #1699); a root shows no Back, and cross-window operation Back returns to its explicit originating surface and route. Nested project and settings routes show only linked ancestors: project overview: `Projects`, project Tasks/Work mode: `Projects › <project>`, settings category: `Settings`. Breadcrumbs end at the parent; the current page appears once as the title. A flat list has none. Back restores the invoker's focus, scroll, filters and drafts (V06/V07). Focus rings use `:focus-visible` for keyboard controls; programmatic heading focus shows no box. Bell, question, Completed and activity entries preserve exact source/scope and return focus through the same Conversations destination. Settings route titles match their list labels; Back restores the invoking Settings row and reading context, including Work mode and Recovery.
- TW2 Placement (points 2 and 4): Conversations native Close and safe Reload remain available outside the failed reader. Back from a failed route returns to a safe view; reopening keeps one main window and never restarts services or work. the menu holds panels, then tasks, then setting links. It holds no composer, conversation, answer card, review or inline confirmation. Task answers, AI requests, the messages list and operation reviews (service, resources, emergency, recovery, update, setup) live in the workspace. A menu click opens the exact workspace context and never sends, answers or confirms. The route families and destinations are the [owner plan review](evidence/1443/owner-plan.md#whole-surface-usability-review); Work mode stays the M12 editor. The menu holds no independent notification, result or closed transcript reader; compatibility entries carry source/scope into Conversations. Settings Work mode and Recovery show current admission/hold state plus direct scope-named reviews, never launch-only pages. Opening applies nothing; all consequential confirmation stays in the existing workspace review.
- TW3 Panels (point 3): Home starts with compact panels: executing workers and reviewers per host and runtime ([running agents](menu.md#running-agents)), work controls, active faults and Messages. Counts are actual executions, deduplicated by board/task/execution. Slots, reservations and Doing/Review task totals stay separately labelled. Stale (over 60 s), missing or partial data shows unknown with its reason, never zero or idle. Empty panels take no rows; the task list follows.
- TW4 AI requests (#1427 kept): the workspace request composer names the project and the runtime. Any available agent runtime opens the session, Claude or Codex; a host with only one runtime uses it and shows its name. With both available the owner picks one; no silent fallback. With none, Send is disabled and states why. Send writes one `<install>/setup/<id>.json` with that `runtime` and launches one visible session through the setup path; the session owns the dialogue. TaskQ stores no conversation.
- TW5 Messages (point 5): Recovery reads existing immutable receipts; it never resends, answers, admits or acknowledges. Unknown source, save or delivery stays explicit. the entrance uses M14 canonical-thread New/Needs me counts, not process or slot counts. Source entries are open `ask` questions (identity: board, task, question revision) and owner-session records with an unread outcome: `launched`, `failed` (no start) or `interrupted` (identity: host, request id, state). Opening an entry acknowledges nothing; Mark read is explicit ([C5](ai-workspace.md)); an unanswered question stays pending until the board leaves `ask`. Drafts and routine updates add none. Archived entries leave the list and the count; a new question revision is a new entry. Unread and archive marks are local view state in `<install>/messages.json`, never task truth (R1). A stale or incomplete source shows the badge as unknown with its reason. One channel (#1918): the badge, entries, task list, dots, icon, notifications and the task conversation read the one tray snapshot with the [shared pending operations](menu.md#shared-pending-operations-1819) applied; an accepted answer leaves `ask` on every surface at once, and no later stale refresh shows the question open again. The single entrance shows independent New and Needs me canonical-thread counts under M14; required questions remain pending after read/clear. A historical resolved question remains readable news/history, never an open answer card.
- TW6 Archive and delete (C7, point 5): any entry can be archived, active and unresolved ones included. Archived opens the archived list; Delete removes one archived entry, Delete all removes every one, permanently, with no undo or trash. Delete acts only on TaskQ message records: the request file, its `<install>/setup/<id>/` folder (brief, launch log, owned attachment copies) and its marks. Archiving a question hides only the local entry; the board task remains.
- TW7 Execution boundary (C7): archive and delete never stop a session, end an attempt, change a task or touch source files or native Claude/Codex chats. A request not yet launched (`state` `pending` or `launching`) refuses Delete with that reason, since the service still needs it. Delete validates that each path lies inside `<install>/setup/`, then reads back its absence; a failed or partial delete names what remains. No hidden recoverable copy is kept.
- TW8 One control, one rule (point 7): a toggle exposes `aria-pressed` with the one selected outline (#1455); a current destination keeps `aria-current`; links and action buttons never show selected state. The task-list state filter is the counter strip (M3): pressed capsules, OR within states, no checkbox group; this replaces the v2 checkbox and select-all clauses (V30/V31). Answers keep source option IDs and revision/operation-ID guards ([answer card](answer-card.md#contract-detail)); only their placement changes. DashQ keeps its own placement.

UX07 Conversations: the selected thread prioritizes its heading, reading content and composer. Secondary thread actions, project selection, launch diagnostics, watch and input limits share one collapsed Details disclosure ([C3/D7](ai-workspace.md#native-dialogue-workspace-c1c9)); supported Attach and Send remain beside the input. Text-only task answers hide Attach and explain that limit in Details. Draft destination stays explicit in one short line; existing sessions keep their recorded runtime. Narrow List/Back, toolbar History and Work sessions, source choices and delivery recovery retain their behavior.

Conversation history (#1918): a task conversation is append-only. After an answer it keeps the question card, then `Answered by <who>: <text>`, then later events; it is never rebuilt from the current task state, so leaving `ask` removes only the composer. Every answered question stays, in board order, each followed by its answer line; a new question appends below them as the live card and replaces none. The snapshot row carries them as `history`: each closed question with the answer that closed it. Worker steps follow the [tool collapse rule](conversations-usability-review.md#tool-collapse-1918).

## Conversations sidebar (#1808)

Reading stays first; secondary controls stay in Details ([UX07](ai-workspace.md)).
Approved: the owner selected Inline actions in [the stage 1 answer](https://github.com/taskqorg/taskq/issues/1808#issuecomment-6490535339). CS1–CS6 extend TW5/TW6 without changing TW7. The [review and editable mockup](conversations-usability-review.md#sidebar-grouping-1808) preserve the current v7 workspace; Inline is the implementation reference.

- CS1 Groups: Recent contains Pinned, then one group per recorded project, then Other. Each nonarchived conversation appears exactly once, regardless of whether it is an owner, task or event thread. Pin takes precedence over project membership. Omit empty groups. Use recorded project identity (registered root and board), never a guessed path or name match. An unavailable former project goes to Other with its recorded name and “Project unavailable”; a global conversation says “No project”. News, current questions, reports, completed history and task activity share these identities and groups; empty activity groups are omitted.
- CS2 Recency: every group sorts by the latest recorded message or task event, descending. Project groups sort by their newest member after pinned and archived rows are excluded. Opening, polling, pinning or collapsing does not manufacture activity. Equal timestamps use stable conversation identity; an unavailable timestamp sorts last and says “Time unknown” with the source reason (D-A19). Active reading freezes row/group order until an explicit view refresh; arrivals never steal selection. That refresh applies recorded recency while retaining selected identity, reading position, draft and keyboard focus. One filtered ordered set also owns Previous/Next, Next unresolved and keyboard moves; opening never changes the order.
- CS3 Headers: show the project name and member count in one button with a disclosure chevron and `aria-expanded`. Project collapse persists by identity across reopening. Pinned and Other remain expanded. Search temporarily reveals matching rows in every active group without replacing saved collapse choices; show matching/total counts. Clearing search restores collapse. An externally opened conversation temporarily reveals its group so the selected row remains findable. An exact external item outside saved criteria is temporarily revealed with its source/scope explanation and Return to view; saved filters remain intact.
- CS4 Row actions: separate Pin/Unpin and Archive icons appear on hover or focus within the row and stay visible for touch. Archive rows expose Restore. Rows retain title, state/attention marker and update age; project names appear on pinned/Other rows, not redundantly inside their own project group. Enter/Space activates controls. Pin moves the same identity; Unpin returns it to its project or Other. No drag order or new sorting preference. Large-text rows use a compact title preview and expose the full title in selection and tooltip; keep typography, colors and bundled icons.
- CS5 Local state: pins, group collapse and archive are local view metadata under TW5/TW6 and R1, never session or task state. Archive removes a conversation from all active groups without stopping, answering or acknowledging it. Archive retains its pin mark; Restore returns it to Pinned or its current project/Other position. Existing Archive, Restore, Delete, Delete all, Undo archive, per-thread drafts and source guards remain reachable. Pending or failed native receipts never claim a completed archive/restore or replay an uncertain action. Retain per-source disclosures, stable content anchor/offset, draft/files/caret and focus through switches/refresh/reflow; restore expansions before anchors. Only Latest resumes following.
- CS6 Search and empty states: Recent search covers Pinned, every project and Other, including collapsed groups; Archive search covers archived conversations. No matches differs from an empty Recent or Archive. Search never acknowledges a question. Narrow List/Back, current thread, composer and existing toolbar destinations stay unchanged. Collapse empty search to its existing icon and view choices into the shared disclosure control with independent full-scope counts; Archive remains directly reachable. Search, project/period/outcome and view criteria feed the same membership/navigation order.

Taskq.md § Product adopts these details (R13). Implementation covers all three thread sources, durable local metadata, authoritative activity timestamps and row actions. Native Mac/Windows acceptance is the release batch under §7.8, as [answered on #1808](https://github.com/taskqorg/taskq/issues/1808#issuecomment-6490079689); a browser mock does not qualify either host (R12).

## Reports and finished work candidate (#1977)

The owner-requested merged destination follows [RC1–RC7](reports.md#conversations-design-checkpoint-1977). The [design review](reports-conversations.md) contains the operator-path comparison, preservation ledger, six-screen reference and qualification gaps. This extends the existing sidebar rather than replacing CS1–CS6; native qualification remains separate from design acceptance.

Keep All / New / Needs me / Needs reply / Decisions / In progress / Finished in one compact view control; empty search stays collapsed. Pin/project/Other membership, row actions, collapse and source timestamps retain CS1–CS6. All includes active conversations, questions and collected finished work. Attention labels distinguish Needs reply, Needs decision, Unread result, Accepted and Dropped; reading alone never displays Decided. Archive is a separate local view, not the Finished filter. Failed or incomplete collections keep cached rows and an unknown reason.

Selecting a result opens it once in the existing reading pane, preserving the sidebar and the previous draft. One board/task identity spans its history, result and decision receipts; the originating PM thread retains the linked outcome without a second standalone result row unless that task was independently opened. Full report expands in the same reading region. On narrow windows, List returns to the same filtered list and selection; choosing a row returns to its reading pane. Legacy Results links and notification clicks open this context directly. Menu Notifications remains a notice/deep-link surface, with no result decision controls (TW2). History and Work sessions remain reachable.

The build must preserve closed-history paging, seen markers, partial draft receipts, local archive/restore, source-numbered answers, per-thread drafts, Watch, attachment limits and execution boundaries. No result/read/archive action may reopen a closed source, release execution or start a held draft. Native screenshots against approved references remain separate evidence (A6, R12); no service update or live installation is authorized by these mockups.

CS1–CS6: each view has its existing bundled semantic glyph, short name and independently counted scope. Active reading freezes visible order until an explicit view refresh; arrivals cannot steal selection. Render 64-row pages with at most 192 resident rows; evict far pages, preserve native scroll and stable source ties, and reject obsolete cursor replies. Query maps retain at most 24 keys. The lightweight Conversations snapshot is capped at 16 MiB; exhaustion reports unknown without deleting its source or retained work. Inactive bodies retain at most eight sources/8 MiB; incomplete counts remain explicitly partial/unknown. Conversations transports task headers separately from revision-fenced current-card bodies. Originating-PM task headers page in groups of 64; one selected linked card reads its body, and all other cards remain reachable without fetching each rendered row. The body ceiling is shared across owner drafts, task cards, results, native closed pages and recorded questions; protected edits and receipts remain pinned with explicit overflow. Current question/result precedes one grouped secondary history disclosure. Completed exposes its active project/period/query/outcome in the collapsed summary; its menu entry forwards without replacing the useful return view.
