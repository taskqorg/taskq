A disposable copy has the same hash. No downloaded executable, install, update, runtime fallback or permission change was used.

The initial `cargo build --locked` in the cold task worktree was intentionally cancelled while compiling dependencies, after the already-present exact release artifact was verified. Its process exit was -1; **the build is not PASS**. Only that build's identity-checked Cargo process and compiler descendants were stopped. No service, tray, agent or other task's build was stopped. The abandoned build is not the source of the tested executable.

`docs/design/tray-fixture.sh` creates three invented project caches in an OS-temp disposable installation. The script's paths and time-dependent generated bytes are hashed in [provenance](provenance.json); raw generated absolute paths are excluded from this public packet. Snapshot children select that installation, disable incident reporting and drop inherited attempt/session/board-token environment bindings. No board or provider episode runs. The production installation's executable is only read/copied; its settings and service are untouched.

## Host and renderer

[Host readback](host.json) records Windows registry build 26300.9711 / 26H2, its registry ProductName, native monitor/work rectangles, effective monitor DPI and scale API return codes, text size and themes. The probe sets only its own thread to `DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`, verifies per-monitor awareness, enumerates monitors through `EnumDisplayMonitors`/`GetMonitorInfo`, calls `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` and `GetScaleFactorForMonitor`, then restores the thread context. Both native scale calls return HRESULT 0. This measures Windows effective DPI, not physical pixel pitch.

[Renderer readback](renderer.json) records `Browser.getVersion` and sampled user agent, DPR, screen/work CSS bounds, viewport and computed fonts from the actual WebView2 snapshot process. A temporary loopback debugging endpoint reads metadata only; it injects no input and uses no device-scale or Chromium platform override. It ends with the disposable process. Renderer DPR and Windows text size remain separate from native monitor DPI.

[Window inventory](window-inventory.json) retains only TaskQ target counts and the locked-desktop predicate from `sky.list_windows()`. It succeeds with zero TaskQ targets. Unrelated window titles and app identities are not retained. No app activation, click, drag, scroll or keyboard input was sent.

[Interactive launch](interactive.json) records a fresh attempt using the same verified release copy, a separate empty-project installation and disposable pinned-window preferences. It exits 1 with `taskq tray already runs on this host`; the subsequent inventory still has zero TaskQ windows. TEMP is not redirected to evade the lock. This is a preserved host guard, not a sandbox denial or a demonstrated UI defect. It leaves all injected and physical interactions Not tested.

## Failure and recovery of the instrument

The first launch used the verified executable at its installed path with a disposable `TASKQ_INSTALL`. WebView2 initialization returned:

```text
taskq tray: WebView2 error: WindowsError(Error { code: HRESULT(0x8007139F), message: "The group or resource is not in the correct state to perform the requested operation." })
```

The process exited 0 but produced zero screenshots and zero metadata samples. This is **Fail**, not a successful capture. The exact cause is unconfirmed; using an isolated store alone did not make this launch usable. No production profile was reset or inspected.

The next launch used the byte-identical executable copied into OS temp. It produced 12 PNGs and the `snapshots in` completion line, but the inherited metadata helper exited without its JSON receipt. The helper's CDP response deadline was unreferenced; when the snapshot child exited, pending reads could disappear with no active event-loop handle. This is a missing-receipt failure, not a metadata PASS.

The one-time helper was corrected to keep the deadline referenced, bound socket-open waiting and write the child exit/result immediately on exit. Only the bounded snapshot measurement was repeated. Final capture **exit 0, 12 scenes, six metadata samples** and retained screen hashes are recorded in [provenance](provenance.json) and [renderer readback](renderer.json). Actual renderer version: `Edg/156.0.4314.50`; DPR `1.399999976158142`. No product code, test assertion or product timeout was changed. Raw logs, abandoned captures and helper files remain in task scratch; the report does not infer a product fix from this instrument repair (§7.4/R12).
