# Operator menu product contract

Accepted direction; implementation target, not shipped behavior. Inherit [M1–M12](menu.md), [C1–C8](ai-workspace.md), [K counters](task-counters.md), [R-UI rendering](rendering-contract.md) and [shared workflow](https://github.com/taskqorg/specq/blob/main/design/workflow.md). This file owns the newly resolved product choices and maps scenarios to surfaces; do not create another menu specification.

## Decisions

- **MP1 Platforms.** Both macOS and Windows retain compact Q and Summary, with the shared six-bin renderer and persisted preference. Custom was retired in #1598; archived Custom controls are not current requirements. Preserve accepted assets, geometry and UI palette; native font/DPI calibration remains I6 qualification.
- **MP2 Work mode.** One editor. Distinguish a rule applying to future matches from an explicit task snapshot. Show matching/excluded tasks, dependencies outside scope and old→new effects for each project. Unsupported intent returns clarification; no silent broader match. Projects outside the change list remain unchanged. “Only these projects” must explicitly include the others' admission changes in review.
- **MP3 Conversations.** Main AI workspace with explicit detached windows; reopening raises the owner. Retain history until deletion; Archive is separate. One active request per conversation; other conversations use configured operator capacity. Drafting remains available. Window close never cancels. A cancellation requires backend acknowledgement and never implies rollback. Dialogue continues in the workspace under [D1–D8](ai-workspace.md#workspace-dialogue-d1d8).
- **MP4 Attachments.** Menu and AI window support selection/drop; proposed initial types are PNG/JPEG/WebP, text/Markdown and PDF. Runtime capability and byte/page budgets remain engineering decisions; present actual limits before Send. Preserve drafts on rejection. Never silently omit a file.
- **MP5 Agents.** Read only / Workspace / Full plus effective Files, Network, Tools and exceptions. Show requested, saved and applied separately; host owns grants. Detailed review candidate: [AS1–AS4](agent-settings.md). UI direction approved; secure grant channel, OS enforcement, migration and default rollout still require P9 qualification. This approval changes no running permission settings.
- **MP6 Emergency.** Emergency stop is required and separate from Pause. Visible fixed top-strip action opens a compact named-host review; confirmation starts stopping immediately. Recovery is a dedicated route under [E1–E5](emergency-recovery.md), not ordinary Play. Drain and Full stop are both required; Full stop may cancel owned local execution offline under R11/E2. Selective recovery follows #1285; native exit and board release remain separate.
- **MP7 First project.** With no usable service, show Set up TaskQ and explicit service/runtime availability. Do not display a Send action that cannot work. Existing-service onboarding stays in AI; zero-service bootstrap uses an inspected setup route and exact external-effects review before installation.
- **MP8 Adaptation.** Keep pinned projects in owner order; accepted default shows three unpinned recent projects ranked by explicit interaction. Attention initially shows two representative causes plus All. Limits are tunable defaults, not reasons to drop urgent items or aggregate counts.
- **MP10 Resources.** Host-owned admission on new qualified hosts, optional strict caps, no Fixed alternative under taskq.md sections3/9; use [dynamic resources](dynamic-resources.md). Existing installations retain policy until reviewed migration.
- **MP9 Scope boundary.** Global machine budgets, cross-project urgency, generic multi-repository execution and transactional plan creation are separate backend work. Show supported routes and explicit unavailable states. Do not advertise missing operations as working.

Inline decisions and AI-led plans: [Q1–Q2 / P1–P6](plans-and-decisions.md), proposed implementation under MP9. Ordinary owner answers need no separate conversation; plan editing lives in the workspace.

## Scenario coverage

| Scenario | Entry → outcome | Required adverse case |
|---|---|---|
| Start a new project | Projects + → setup/AI → reviewed registration | No service, auth missing, existing files preserved |
| Plan or clarify work | Menu composer → conversation → proposal/result | Attach rejection, stale proposal, partial apply |
| Focus several projects | Work mode → rule/snapshot → per-project review | Unsupported intent, external dependency, Mixed |
| Answer / inspect failure | Attention or Human counter → explained inline choices → matching receipt; Failed → linked context | Stale board, inaccessible local session |
| Inspect execution | Project → task → local session; remote host indicator | No valid permalink; no invented remote link |
| Pause intake | Named-host pause review → readback | Existing attempts continue; partial target failure |
| Emergency stop | Fixed stop action → target review → stop progress | Unknown process, failed termination, offline board |
| Recover | Held banner → per-attempt reconciliation → reviewed resume | Dirty work, uncertain side effect, old attempt still live |
| Tune agents | Settings → Agents → effective policy → change review | Unsupported sandbox, old policy still active |
| Find an AI window | AI conversations list → raise selected owner | Restart/interrupted delivery; no duplicate request |
| Change tray view | Settings → Appearance → compact Q / Summary → immediate local preference | Small Windows slot, DPI/theme change, overflow |

## Accepted placement

**Workspace review is accepted.** The menu remains a quick controller; Work mode and recovery open a full-width workspace page beside conversation/session navigation. Preserve targets, context and drafts; reopen the existing workspace, never a duplicate.

[Earlier comparison](menu-next-variants.html) is historical. Menu review is not an active alternative. [Integrated prototype](workspace-prototype.html) shows only Workspace review, with menu, conversations, work sessions, Work mode and agent settings reachable. Placement approval does not approve unresolved safety/backend mechanisms.

## Dashboard decisions (#1573)

The [frozen reference](exploration/control-panels.html), marker `conversation-walkthrough`, governs menu/settings geometry. Current taskq.md overrides the historical package: Preact/Signals/Wouter, Held without Closed, visible owner sessions and current archive/execution ownership remain. Conversations implementation belongs to #1580; session-link adapters belong to #1565.

- **MP11 Working views (O2, O3).** State and project filters combine OR within each set and AND between sets and search. Empty selection means unrestricted. Changes apply immediately to the selected view's working context. Only Save replaces its preset; one-click Reset restores the saved criteria and query. Retain each view's working criteria/search, list scroll and selection across switching, navigation, Settings, close/reopen and restart. Shortcut pin/unpin affects shortcuts only; delete custom views directly under [P-V1](#saved-view-deletion-p-v1); built-in views stay. View conditions and Saved views open in one owned View window ([P-W4](#windows-and-task-pins)); the list stays in place; one fixed-order column of states, no reorder editor or drag handles. Combined and project-grouped lists use Doing, Review, Ask, Failed, Ready, Blocked, Later, Held, then priority, ascending issue number, canonical forge/server/repository identity. Local registration paths never break ties. All shows the deduplicated total for selected projects/search before state filtering; All removes only the state restriction. Clearing project scope is explicit in the editor. Partial counts stay unknown. No Closed counter. Existing explicit preferences survive migration. Filters never change queue admission.
- **MP12 Navigation.** One/two-row useful host status; tasks dominate. The menu header holds one Conversations/workspace entry plus Settings, replacing separate Inbox and Conversations icons. The entry shows a deduplicated count of source-backed unread/actionable events and opens the relevant Inbox or Conversations section; when both have events, an actionable question/failure comes first, the other section one tab away. With no events it restores the last section/selection. Opening the window alone does not acknowledge events. Badges reflect actual request/Inbox events, never invented native unread replies. A stable top action row precedes section titles; a long title or breadcrumb uses the row below. Home returns to tasks in one activation without clearing working context; Back stays. Appearance holds tray icon, font and window preferences. Pin controls window lifetime; the separate frequent Always on top action uses overlapping squares with a filled foreground square. The menu has no Enlarge; its footer shows the version only plus the corner resize grip. Shared Lucide/provider assets and accessible anchored popovers serve both menu and workspace.
- **MP13 Task inspection (O1).** Rows show current stage and its elapsed time only; the runtime mark and, for proven remote execution, the remote mark sit immediately before it. The existing identity anchor looks interactive. Click, Enter or Space opens anchored details; hover and focus never open them, and a refresh never opens a panel. Details put the current question/problem, numbered answers, result and useful actions first; host/runtime/session, technical IDs, total task age, completed step count and ordered stage durations disclose on demand. Full wrapped titles remain direct issue links. Missing/invalid timestamps remain unknown. Elapsed time alone never establishes a stall. No right ellipsis, chevron or extra action column.
- **MP14 Hosts and Completed.** By default one compact expandable line shows each named host and separate Claude/Codex running-agent counters with the bundled marks. Expansion shows CPU/memory with units, freshness and resource detail; it separates executing processes, occupied slots, reservations, policy ceilings, admission and board counts. Stale/unknown counts stay explicit, never zero; a global count is never labelled as one host. Completed is a direct task view with project, period, search, outcome/PR and history; success, cancelled/not-planned and unknown closure stay distinct. Board history is read on demand with pagination, not a new task store; activity counts never substitute for task history. Completed adds no Closed counter.
- **MP15 Settings routes.** Each Settings entry reaches one coherent surface: Settings, Appearance, Hosts/resources, Work mode, Agents/access, Projects, Delivery, Services, Notifications, Activity, Recovery and About. The host service appears once per host; projects reference it with readable names. Show effective state, freshness, relevant controls and one precise unavailable reason instead of repeated prose, raw paths or circular placeholders. Old request prose, revisions and technical identities sit in details. Menu/workspace footers show the version only and the integrated corner grip. Access, Delivery, Resources, Notifications, Recovery and service operations keep their existing authority/review/readback boundaries; no new grant, model or execution-policy effects. Agents version and sign-in follow [AS5](agent-settings.md#as5-version-and-sign-in).

These owner corrections (#1657) govern review candidates; they do not assert shipped behavior or approve new lifecycle/transport mechanisms. Theme colors and the eight task-state icons live in the [visual system](visual-style.md#task-state-icons). Workspace dialogue follows [D1–D8](ai-workspace.md#workspace-dialogue-d1d8); Custom stays retired (#1598).

## Saved-view deletion (P-V1)

Owner accepted option A on [#1657](https://github.com/taskqorg/taskq/issues/1657). Put Delete beside each custom view in the Saved views section of the View window ([P-W4](#windows-and-task-pins)), available by pointer and keyboard. Keep built-in views; distinguish deleting a view from unpinning its shortcut and Resetting working criteria. Do not add a Settings detour or task-row controls.

Deleting another view leaves the active query, selection and scroll untouched. Deleting the active view restores All tasks with its existing working context. The View window stays open and shows a named deletion receipt with Undo. Keep a single latest undo record without a timer through navigation/reopen/restart; it contains the saved criteria, unsaved working context, original position and shortcut state. Undo restores the view and its context. Restore selection only if the user has not changed the fallback context since deletion; otherwise keep their current work. Never overwrite a conflicting restored identity. Only the latest deletion is undoable.

Deleting a view removes its shortcut and preference only; tasks, history, global task pins and conversation drafts stay intact. Prototype custom-view examples are labelled fixtures, not real saved views or a default. Native persistence, write failure and concurrent preference changes need implementation evidence.

## Windows and task pins

The owner accepts separate Settings windows and a global task watchlist (#1657); P-W3 carries the owner's window corrections from the same review. P-W1 supersedes the earlier per-view/filter-scoped pin proposal. Incidental geometry/defaults and native qualification remain separate from these decisions.

- **P-W1 Global task pins (accepted).** A task pin is one personal canonical board reference shared across all saved views, not a board priority/state change or a detail latch. Pinned tasks always come first in the same watch section above filtered results, including when project/state/search excludes them. They use ordinary compact task rows; click/keyboard opens details. Pin closes the detail card, never leaves an expanded task behind. Pins keep insertion order and appear once: matching pins are removed from the ordinary list. View counts retain their criteria and do not include unrelated pins. The menu has one shared content scroll for host detail, pins, filters and results; no independently scrolling task/pin subpanels or sticky watch overlay. Pins retain their top order, not a fixed viewport position. Only window controls and the version/resize footer stay outside this scroll. Save, Reset, switching/deleting views and restart retain pins. Unpin returns a matching task to comparator order; an excluded task leaves the visible list. Keep completed/unavailable references with their sourced outcome or explicit unknown until unpinned. Persist references/preferences only; task truth stays on the board. Migration unions prior per-view pins without duplicates. New users start with none; prototype pins are fixture data.
- **P-W2 Separate Settings (accepted).** Settings opens/raises one owned window, preserving the task menu's filter, selection and scroll. All Settings subsections stay in that window with Home/Back. Closing hides it without resetting section/drafts; reopening raises it, not a duplicate. Operational review placement and authority stay unchanged. Prototype foreground switching represents separate windows; native simultaneous placement remains unqualified.
- **P-W4 View window (owner request #1700).** View conditions and Saved views open/raise one owned View window, superseding the anchored menu overlay. It has compact sections in one content scroll: Saved views, Projects, then States or Period/Outcome; Display, Save, Reset and Done stay in a fixed footer and Close in the header, reachable without scrolling at default size with eight projects. Working changes apply at once to the menu; Save stays explicit; Reset is one click; Delete, Undo and protected built-in views keep [P-V1](#saved-view-deletion-p-v1). Closing hides it; reopening raises it. A capture or browser surface without native windows keeps the overlay.
- **P-W3 Common window chrome.** Menu, Settings, View and Conversations use the same TaskQ-owned draggable header, close/hide, Always on top, focus and corner-resize language, without a second OS titlebar. The menu has no Enlarge control; keep its corner resize grip. Settings and Conversations retain enlarge/restore. Header actions never start a drag. Only a transient menu needs Keep open; ordinary Settings/Conversations windows already remain open on blur. Always on top is independent. Pinning a task, keeping a menu open and changing z-order have distinct accessible names and effects. Native hit-testing, task switching, accessibility, multi-monitor placement and keyboard behavior require platform evidence.
