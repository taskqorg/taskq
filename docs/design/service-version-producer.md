# Service-version producer

## Contract detail

`diagnostics` in the host heartbeat and local status, and each § 5 JSON host row, reports schema 1 and the public `service` identity. Running comes from the publishing binary; selected comes from CoreQ `Tool::current()` with the `current` file modification time; reported CoreQ version comes from the immutable Cargo.lock build input. Each field carries its source, producer time, value, state and safe reason. The service samples this projection at most once per 60 seconds per project; heartbeat/status reuse preserves that sample time and the existing board-write budget. No remote lifecycle authority is added.
Health reports only the running release's regular `healthy` marker and its modification time: the § 8 consumer rollback-window/publication check, never workload or integration health. A marker older than this service process, or within its unordered start second, is last known, not current health. Lifecycle is `healthy` only from that fresh marker; a pending selection with retained children is `waiting`; otherwise a matching selection without a fresh marker is `starting`. Unsupported checksum/rollback evidence stays unknown, never inferred from version order. Available release/check time remains unknown without a retained release-check receipt; a fresh process alone does not prove an available/current comparison.
Host observation time uses the producer clock; board heartbeat freshness uses board time (§ 4). Readers mark expired/future or failed-source observations unknown/stale with reasons, retain last-known versions and source times, and clear current health. Missing, duplicate, malformed or unsupported diagnostics read unknown. Local status freshness remains § 4; no raw paths, errors, commands or lifecycle-store receipts are published.

Workload/integration recovery, remote controls and other-host rollout remain outside this handoff. Available release/check time and unsupported checksum/rollback stages remain explicit producer gaps; do not exercise upgrades merely to populate them.
