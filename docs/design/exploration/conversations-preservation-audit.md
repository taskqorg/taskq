# Menu and Conversations: functional preservation audit

This audit corrects the earlier candidate's scope claim. The handwritten candidate is an interaction experiment, **not a complete replacement**. Its 19 behavior checks and 40 geometry cells do not establish functional parity. No production source was changed; no feature removal is approved.

Baseline: `da4ef2b6db01b066f5c897eb5afe01269fda37df`, current source read on 2026-10-28. Scope includes both windows, shared answers and every reachable Settings/operation route. Source presence means implemented code exists; it does not prove a feature works in the installed binary. Every native result below is **Not tested** for the proposed interface.

## Decisions and source of the gaps

The old candidate reimplemented selected scenarios with fixture data. It did not load the real menu, conversation or answer-card components. That omitted full filters, view management, task controls, command history, rename, owned-file handling, watch, detached windows, permanent deletion, event management, operations and most Settings. These omissions are defects in the review artifact, not authorized product cuts. The old candidate also invented known-count history geometry, provider events and manual theme switching; none defines the production adapter or OS theme policy.

**Retain all functional groups below.** Simplification changes hierarchy and default disclosure. It does not erase a capability, validation, authority check, native persistence, fallback, operation identity or recovery path. Changes to geometry, compact question entry, fixed input and scoped feedback remain proposals. Canonical contract reconciliation precedes implementation (R13).

The source-backed review uses current components for retained controls; the interaction lab demonstrates the proposed long-history and delivery behavior. Native effects in both remain simulated. A control being rendered is weaker evidence than a successful end-to-end journey.

## Nontechnical daily journeys

UX07 implementation: [#1771 preservation and before/after evidence](../review-evidence/1771/review.md) maps the affected groups below to the existing executable journeys. Secondary controls move to one collapsed Details disclosure; no capability, export, authority or storage format is removed. Browser passes do not qualify native clients.

1. **A question needs me.** See the task state and short reason in the menu. Open the exact question in Conversations. Read the problem, same numbered choices, recommendation and checked evidence. Choose a normal option or write an answer; consequential actions show what will happen first. One nearby status says whether the answer was accepted. Return to the original menu view/position. Looking at a task does not mark it read.
2. **I want to ask the PM.** New → registered project → ordinary request → Send. See a visible delivery result, then that session's work state and reply. Type the next message while it works. Continue in the same thread; runtime/host details are available without teaching the person about operation IDs. New from draft explicitly starts a separate request.
3. **I need an old decision.** Search/select the conversation, scroll upwards without losing the composer or moving when output arrives. Load earlier also works by keyboard and after a read error. Jump to latest is explicit; returning restores the message/offset. Native source remains authoritative, and the beginning stays reachable.
4. **I cannot decide now.** Later parks the task with its real lifecycle semantics; Archive hides a local conversation/event only. The UI names the difference. Archive has Undo/Restore. Permanent deletion is scoped, confirmed and preserves an independent unsent draft; it does not stop a worker or delete a native chat/board issue.
5. **Something takes time or fails.** Show Sending → accepted delivery → working/elapsed → reply, with failures placed at the relevant step. Unknown delivery means Check delivery, not Send again. Definitive refusal keeps editable text/files. A save failure is separate from a provider failure. Search, navigation, typing and Close remain usable throughout.
6. **I need to organize work.** Search/filter several states/projects, save a named view, pin its shortcut, group by project, pin a task globally, visit Completed and restore previous conditions. Ordinary discovery stays in the menu; configuration opens View/Settings in the existing separate windows.
7. **I need more control.** Work sessions, Open native session, Detach/Return, rename, command history, files and Watch remain reachable from their existing context. Watch explains that it may send future prompts; it is never enabled by browsing. Technical identifiers and diagnostic receipts are disclosed on demand.
8. **I need to change the service.** Use the existing Settings route and reviewed target/effect. Pausing admission, draining, full stop, restart, uninstall and recovery retain different meanings. Configured/applied/observed state never collapse into an optimistic success. The mock sends no real operation.

## Required planning gate F0

Before any implementation: attach a source baseline and a completed target-location map for these groups; reconcile #1720/#1723/#1738 and existing outcomes; retain source exports and shared consumers; identify deliberate behavior changes separately from fixes. Any proposed removal requires its user problem, usage/source evidence, replacement path, data/recovery consequences and an explicit owner decision. Empty cells or “later” are failed parity coverage.

Implement one reversible slice at a time: compact menu cue; stable reader/input; selected-thread feedback; bounded history; daily native PM qualification. Each slice preserves existing functions, has its own relevant adverse cases, and ends in a usable state. Keep current native persistence/adapters and framework. No full rewrite or new task/transcript database is justified by this review.

## Evidence and limits

- Earlier mock: 19 targeted behavior groups and 40 geometry cells passed for synthetic data. They remain useful for those named interactions only.
- Source-backed review: the final check passed 17 behavior groups including 144 geometry cells, with no page errors. Hashes and an explicit patch list record reused source; full fixture results are written by its check script. Source reuse preserves reachable controls and validators in the artifact but cannot establish native authority, storage, windows or provider behavior.
- Release acceptance: all affected ledger journeys plus Q-A1–Q-A12; relevant current browser/Rust tests; installed macOS/WKWebView and Windows/WebView2 with actual Codex and Claude. Record Pass/Fail/Not tested with source/binary and renderer identity. No installed-native or real-provider result is claimed here.
- Current source is a baseline, not a design ideal. Existing documented scroll and cross-thread feedback defects must not be preserved as desired behavior. Full unchanged source reuse alone is not proof of improved usability.

## Presentation correction: all three gates together

The first source-backed revision preserved controls but restored old visual clutter. That revision is superseded as a visual candidate. Source reuse cannot override the approved visual system or substitute for full interaction review.
