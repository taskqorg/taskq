# Test selection

TaskQ applies [SpecQ testing](https://github.com/taskqorg/specq/blob/main/engineering/testing.md). Run `python3 scripts/check.py` from a checkout. `--base SHA` selects the entire change since that immutable base; CI sets CHECK_BASE to the merge-group base or PR base. Unknown/unavailable impact broadens to the full relevant Rust suite. No changed-file list means full, never an empty passing gate.

Development loop (workers and reviewers):

- While editing, run only the affected checks: a filtered `cargo test --locked <module or test name>` for the changed Rust behavior, or the changed `node tests/<name>.test.cjs` for a web component.
- Run `python3 scripts/check.py` once on the result candidate, after the rebase and before `result` (taskq.md § 7 step 4). A reviewer runs it once on the exact candidate under review when the candidate's evidence leaves it unknown.
- Do not rerun the full `cargo test --locked` or `check.py --full` after each edit. A repeat full run needs a named reason: the selection changed, the edit touched shared code (build, dependencies, configuration, `core.rs`, board or runtime modules), or the previous run failed.
- The SpecQ run policy still applies: new and previously failing checks run locally, a defect fix reruns its reproduction, and unknown impact broadens to the full relevant suite. A check that did not run is reported as not run, never as a pass.

- Prose-only changes use documentation/whitespace checks. Root contracts and agent entrypoints count as shared behavior. Asset-checksum pages run their component checks.
- Web-only changes retain the Rust state model and all cheap Node component/IPC checks. Rust, fixtures, dependencies, build, configuration or unknown files run `cargo test --locked` and offline selftest in a temporary installation, never the running host store. New and previously failing checks belong to the affected selection; unresolved failures block acceptance.
- Builders need Node.js20+ and npm. The canonical gate runs `npm ci --ignore-scripts --no-audit --no-fund`, validates the JS module/effect inventory, and bundles the same immutable CoreQ revision used by Cargo. Installed binaries need no Node.js/npm. Browser instruments consume `build/web` artifacts; generate once with `npm run build`.
- CI events: `pull_request` runs the selected Linux Rust and Node checks, a fast signal for workers and reviewers. `merge_group` runs the full affected-OS matrix and is the merge gate; `close` publication needs it green (taskq.md § 7). A push to `main` runs no test suite in tests.yml; cache.yml only builds dependencies and test binaries per OS to save the Rust cache that PR and `merge_group` runs restore. `workflow_dispatch` runs the full matrix.
- Node checks run once on the Linux CI runner. In `merge_group`, Rust checks run on the affected supported OSes; shared/build changes use Linux, macOS and Windows. Prototype/browser instruments and paid/native matrix cases remain separate; run the affected instrument when changing its layout or the instrument itself. A local gate runs changed `tests/*.browser.cjs`; it requires the already documented Playwright setup and safe launcher. Browser or native absence is an unverified claim, never a pass. Native click and window-raise behavior is owner-observed, not a required gate ([UI acceptance](design/ui-acceptance.md#hard-gates)).
- One elapsed budget:900s per GitHub-hosted ubuntu-latest, macos-latest or windows-latest runner, from toolchain setup through build and execution. The command prints elapsed time and fails on expiry, with no retries. Dependency checkout is provided by CI; its job timeout also bounds runner setup. Local timings name their host/cache state and do not qualify cold CI timing. Budget excess requires diagnosis, not omitted checks.
- `--full` runs the full Rust regression suite plus Node/artifact-script checks. Validate selection on workflow dispatch, shared-code/build/dependency changes and before release/dependency-pin adoption. A selector that misses a failure must be repaired before reuse.
- Release publication (a `live` push) refuses a commit not on `main` and waits for successful tests.yml on that exact commit: its merge-queue `merge_group` run (or a `workflow_dispatch` run on `main`); a newer completed failure refuses, builds with --locked, and tests the staged artifact. Native client, lifecycle, outage and UI acceptance run when their behavior or environment changes; source CI alone never authorizes production intake.

Keep the revision/diff identity, command, result, elapsed time, runner/tool versions and relevant native log or sequence with acceptance evidence. Remove an obsolete assertion only after naming the retained check that protects its risk. Core/receipt behavior and public asset hashes remain protected by their existing checks.

Windows loader-layout protection lives in `platform::tests::installed_windows_release_starts_without_build_paths`: the relocated executable and actual CoreQ launcher run the existing offline selftest through an owned test-process fixture with only System32 on PATH. It replaces `tests/windows_install.rs`, whose fake child status relied on obsolete legacy install/reload behavior. Legacy-owner refusal is protected by `host::tests::host_install_refuses_unresolved_legacy_owner_without_effects`. This native-free layout proof does not register a real host unit or qualify product installation; staged product-binary selftest and H-A5 native installation remain required.

`tests/telemetry_process.rs::commands_collect_without_configuration_and_flush_on_exit` also runs the actual installed launcher/release and macOS bundle without ambient install selection. Each entrypoint must commit its own history under its existing install, leaving an isolated OS default untouched. CoreQ's shared entrypoint matrix protects override, alias, renamed-launcher, broken-layout and first-install smoke rules. The same TaskQ file's collector-qualification case closes the real stderr pipe before ordinary help with an unavailable store, corrupt diagnostic control or invalid inherited context; optional reporting must preserve the command result. Its incompatible-writer case holds a resident writer with the v4.6.19 IPC budget; Resume receipts in the shared export, checksum refusal and actual updater activation must pass without a side store (#1294). The release download is substituted, not checksum or selftest. The macOS installer fixture also exercises a live legacy-budget writer and second-root attachment with its existing substituted native manager. The cross-platform Stop process chain includes missing telemetry while retaining ownership, replay, drain and exit guards. Its staged-selftest case stops the resident writer (unix SIGSTOP); the candidate offline selftest must still pass and leave the shared store unchanged (#1419). These are process proofs, not native service or rendered UI acceptance.

On macOS, `host::installation::tests::interrupted_restore_never_reactivates_the_failed_installation` runs the existing installer process instrument through `tests/fixtures/install-process-macos.py`. It kills the caller between restoration writes and checks exact same-command restore, no native submission and verified actor teardown. The instrument's wider crash/attach cases also run real project loops against in-memory boards; its native manager is substituted, so it does not qualify installed/native product lifecycle.

The same restore case requires the first topology originals to retain prior rollback-floor bytes; the legacy handoff case requires recorded original absence. The floor also gates legacy launchers, so reverse qualification cannot guess its pre-host state. These checks preserve reverse inputs; they do not run or accept a reverse installation.

The same instrument's normal `legacy_handoff_preserves_active_work_before_native_retirement` case starts legacy supervision with an owned bounded child in the existing recovery format. It checks that host startup cannot retire the child/legacy owner or acknowledge the project before exit, then runs the actual drain/controller/retirement and same-command recovery. The controller continues the same trace through a child span; the fixture's simulated native Stop asks only its exact legacy process to self-exit. The substituted bootout waits for the fixture parent to reap the exact legacy process and acknowledge its creation identity and successful exit; a zombie cannot be treated as native absence. Exit readback covers the child and controller; forced fixture cleanup fails the case. This is source/process connection proof, with separate native-manager and installed qualification.

`telemetry::tests::live_semantics_use_the_installed_capture_and_leave_no_legacy_sink` submits all five typed product record kinds through real capture, then reads typed committed records and checks context/version and the absence of the old sink. Its real request producer sends a16–64KiB summary, requires multiple stored parts and restores every counter; deleting the final part must make the product report unknown. Existing profile/request fixtures retain fixed-clock report, ordering, corrupt-input, unknown and normalization coverage. The no-host repair case compares typed history before/after repair and independently requires the original archive text bytes to survive. Shared-store conversion and migration checks retain receipt-clock, split-group, source-identity, replay and privacy protection; typed reports do not bypass those boundaries. Copied-history comparisons use equal retained input and preserve the original files; elapsed time and RSS from one warm run are observations, not installed performance acceptance.

`board::tests::native_http_preserves_refusal_without_exporting_request_data` keeps its15s process deadline and real curl/local-server boundary. Its owned child records fixed-code phase timings around capture setup, HTTP exchange, collector qualification and teardown, so a timeout names the last observed phase. This diagnostic does not attribute a previous timeout or weaken the deadline.

`profile::tests::concurrent_appenders_keep_records` requires 200 concurrent producer records to commit, then holds the shared budget lock until one more record's commit meets it, and parks that commit in the store write lock through a flush. The flush must read unacknowledged; after release the record commits with no loss or failed batch, and all 201 records export. #1333 cause: CoreQ's flush wait (10 s since #1303) equals its writer retry window, which starts when the 5 ms coalescing timer begins the commit; a test-thread stall over about 1 s before the flush let the window expire first (`telemetry installation budget lock unavailable`, lost 1). This was fixture timing, not a CoreQ pin regression: the #1323 pin left capture and broker unchanged. The write lock blocks without a deadline, so the outcome no longer depends on scheduling. `retained_profile_report` separately checks actual text rotation followed by a new typed record. This replaces its duplicate producer/rotation race, which incorrectly treated optional queue admission as a durable commit despite the specified1s lock deadline.

Tray effect checks cover same-ID coalescing and changed-payload refusal, bounded Add admission after presentation dismissal, generation-bound late results, explicit picker cancellation/error and exact path decoding, attributable answer/resource outcomes and Pause independent of a blocked answer. The Add outcome check also requires failed capture for logical failures/panic and refuses new admission after uncertain panic. Native picker and terminal lifetime are separate from short launcher submission; source checks do not prove a visible OS window or successful resource installation.

`host_policy::project_run_waits_for_the_host_owner` bounds each invocation at 60s on Windows and 10s elsewhere, including startup and native ownership discovery. It logs elapsed observation time on success and failure. The existing no-project-scheduler and unchanged-owner assertions remain mandatory; no retry is allowed. This fixture budget does not change native-read or telemetry receipt deadlines.

`host_policy::capacity_command_changes_host_policy_not_project_settings` bounds each `taskq` invocation at 60s on Windows and 10s elsewhere and names the command and elapsed time on timeout. Its assertions remain mandatory; no retry is allowed.

`telemetry_process::emergency_state_survives_failed_wakeup_and_notifies_other_projects` uses the existing bounded process exchange for each CLI invocation (60s Windows, 10s elsewhere), accepting expected nonzero exits for assertion checks. Phase timings distinguish each Hold/Release, opening the telemetry reader, export and cleanup. The merge-group Windows run for #1467 exhausted the unchanged 900s gate here without identifying the stalled phase; bounded CLI exchange and diagnostics do not establish that stall's cause. Every hold-state, notification and durable-error assertion remains mandatory; timeouts fail without retry.

`telemetry::tests::older_tray_writer_hands_over_to_new_host` covers #1309 with separate old-tray and new-host processes. An incompatible protocol or refused handshake must yield through the existing tray heartbeat, preserve old history and commit a new command receipt. A stale heartbeat must remain unchanged and its writer alive. The host invokes recovery only after taking its installation owner lock; store errors do not trigger takeover. This fixture substitutes the tray event loop and does not qualify an installed native upgrade.

The incompatible-writer process case enables CoreQ store/IPC phase diagnostics in the resident writer and candidate selftest and prints them with the selftest output. #1303 cause: CoreQ flush waited 3 s, shorter than one bounded Remote append (connect 1 s, write 1 s, ack 2 s, reopen, one retry). CoreQ `flush_outlasts_one_slow_bounded_remote_append` reproduces the failed Windows signature (`batches 0`, `inflight` nonzero) with a 4 s append at 3 s and passes at 10 s; CoreQ flush and required commit now wait 10 s. Which IPC phase made the Windows append exceed 3 s is unknown; #1315 investigates it. Every handover assertion remains.

`enrollment::tests::sender_sends_only_the_approved_board_and_never_blocks` prints the cost of the state read, CoreQ active read, record build, resources read and the tick with its thread spawn, on success and failure. #1328 cause: each CoreQ connection load protects its folder through `whoami` and `icacls` on Windows, and the pass ran up to four loads before spawning. Those loads now run on the delivery thread; the 2 s bound and every assertion remain, with no retry.

#1376 cut the slowest Windows unit tests without removing an assertion (windows-latest, debug, before/after): the non-macOS icon path filled each rectangle over the whole mask with 16 samples per pixel; `fill_rect` now visits only the pixels the rectangle covers, with the same coverage, so `icon::tests::summary_aligns_by_ink_and_stacks_on_one_scale` went from 90.3 s to 5.0 s and `tray::tests::history_grid_moves_one_bin_at_a_boundary` from 18.7 s to 1.5 s, with render hashes equal on both paths. `telemetry::tests::archive_pressure_refuses_growth_without_deleting_history` bulk-loads its first 440 rows in one transaction; the per-row append, refusal, preserved-archive and history checks still run near the ceiling (49.1 s to 5.3 s). `service::tests::simulated_six_project_day_fits_a_thirtieth_of_the_store_cap` extrapolates from 3 of 96 intervals instead of 6; the estimate stays within 3% and the 1/30 cap assertion is unchanged. `tests/host_restart.rs` no longer compiles its Windows PowerShell inventory shim with `rustc` during the test: `cargo test` builds `tests/fixtures/native-inventory-windows.rs` as the `native-inventory-windows` example in parallel with the crate, and the test copies it; a run without examples (`--test integration`) still compiles it. The shim's smoke check and every restart assertion are unchanged. The six `tests/*.rs` files are modules of one `tests/integration.rs` binary (`autotests = false`): one link and one parallel harness instead of six sequential binaries; every case and assertion is unchanged, and `telemetry_process` re-runs its ignored collector as `telemetry_process::resident_analysis_owner`.

`host::tests::local_capacity_saves_while_telemetry_is_stalled` covers #1351: with the shared budget lock held, a tray limits request must save in under 3 s and a stale request must leave host.json bytes unchanged. Before the fix it was rejected after 10.13 s with `telemetry required record unacknowledged`. `control::tests::observation_never_waits_on_a_stalled_receipt_commit` and `tests::focus_never_waits_on_a_stalled_terminal_receipt` replace the checks that the signal lock stayed held through a blocked receipt commit, which #1351 removes; they hold the store write lock, require the command and the next writer to proceed within 2 s, and still require the receipt to land with its original span after release. Lifecycle receipt-refusal cases now require the operation to proceed; a missing collector still refuses as before (`direct_focus_commands_cannot_bypass_required_receipts`, degraded Stop).

## Build cache

A new task worktree reuses compiled dependencies through `sccache` (#1604, taskq.md § 8). The service sets `RUSTC_WRAPPER` to the `sccache` it finds on its own `PATH`, unless it inherits `RUSTC_WRAPPER` (an empty value is the owner's opt-out). Claude children get it, background turns through their settings `env`; Codex children get it only without a sandbox (`danger-full-access` or the bypass flag). Children in taskq's Windows or Linux sandbox or in Codex's own sandbox cannot reach the user cache or the local sccache server, so they build unchanged. At start the service logs one `build cache:` line naming the wrapper or why there is none; a host without `sccache` builds unchanged and never fails. Install or remove `sccache`, then restart the service.

- Where: sccache's default per-user disk cache (macOS `~/Library/Caches/Mozilla.sccache`, Windows `%LOCALAPPDATA%\Mozilla\sccache\cache`, Linux `~/.cache/sccache`) or `SCCACHE_DIR`. sccache evicts the least recently used entries above `SCCACHE_CACHE_SIZE`, 10 GiB by default; `sccache --show-stats` shows use, and deleting the folder is a safe cleanup. `taskq cleanup` still removes closed-task worktrees with their `target/`.
- What it saves: registry dependencies, compiled once per host. Workspace crates build incrementally and binaries and proc-macros link, which sccache does not cache; each worktree keeps its own `target/` for them.
- Seeded `target/` (#1620): before a worker's first start the service creates `.worktrees/taskq-<N>` (fetch `origin main`, then the existing `taskq-<N>` branch or a new one from `origin/main`) and clones into it the newest `target/debug` of the project root or another worktree; the worker continues that worktree (taskq.md § 7). A recent source shares the current `Cargo.lock`, so only the workspace crate recompiles. macOS clones by `clonefile` (APFS copy-on-write, one call); Linux uses `cp -a --reflink=always` (btrfs, XFS); Windows and ext4 skip. The clone only reads its source and each worktree owns its copy, so no two worktrees share a `target/`. The seed is skipped when the worktree already exists, the role is a reviewer or a resume, or no `target/debug` exists; a skipped or failed seed logs `#<N> seed skipped: <reason>` and never blocks the start, and the worker then creates its worktree itself.
- Seed timing (mac, 8 logical CPUs, load average 13-26 from other workers, sccache on; first `cargo test --locked --bin taskq selftest` in a fresh worktree of `0bc5c954` after `npm ci`): unseeded 133 s; seeded from the stale root `target/debug` (older `Cargo.lock`) 112 s; seeded from a `target/debug` built at the same `Cargo.lock` 57 s, only `taskq` recompiled. The `cp -c -R` copy of a 14 GB `target/debug` took 11 s; `clonefile` on the directory is one call.
- Parallel workers: each worktree keeps its own `target/`, so no cargo build lock is shared; the sccache server serves concurrent compiles. A shared `CARGO_TARGET_DIR` was rejected: cargo locks it for the whole build.
- Hosts: mac has Homebrew `sccache`. Windows has none; the owner may install it (`winget install Mozilla.sccache`). FRA uses it only if `command -v sccache` finds it on the service `PATH`.
- CI keeps its own cache: cache.yml, tests.yml and release builds are unchanged and set no wrapper. The service's own builds (`scripts/dev-install.sh`) run without it.
- Failure: a wrapper whose server cannot start or answer fails the child's compiles (`sccache: error: ...`); `sccache --stop-server` resets the server, and removing `sccache` from the service `PATH` with a restart turns the cache off.
- Timing (Windows 11, 16 logical CPUs, cargo 1.99.0 GNU toolchain, sccache 0.18.0; first `cargo test --locked --no-run` in a fresh worktree of d5ec861 after `npm ci`; another worker's four builds shared the host, so wall times are noisy): no wrapper 703 s; sccache with an empty cache 418 s (144 misses, 139 MiB stored); sccache warm 769 s with 116 of 144 compiles hit (80.6%). Two warm fresh worktrees started together took 493 s and 501 s, both at 80.6% hits; neither waited on a build lock, only briefly on cargo's package-cache lock at start, as without a wrapper. The taskq crate's own test and binary builds, which sccache does not cache, dominate wall time; the saving is the dependency compiles. Test execution does not use the cache. mac was not measured.
