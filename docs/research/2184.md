# #2184: Native A6 qualification of #2151 protected authority on Mac

## Question

Does the merged protected app-server adapter (#2151, commit 2b8f14d8) pass native preparation, descendant completion and recovery on the Mac under the existing Workspace authority, without a grant change, an install of unmerged code or a paid model turn?

## Findings

- A worker cannot run the check. The installed adapter refuses a worker caller before dispatch: "a worker cannot launch or control external app servers" ([#2151 comment](https://github.com/taskqorg/taskq/issues/2151#issuecomment-6576970302)). The §3 external-slot boundary keeps this refusal, so the PM ran the native driver as the owner-account consumer.
- Run 1 (16:40Z) hit an open gate. The Mac service was in a pending update handover (#2209), which held every launch. The slot stayed queued and was denied after 290 s; no native stage ran ([run1-gate.jsonl](../evidence/2184/run1-gate.jsonl)).
- Run 2 (16:48Z), after the 16:46Z service restart, passed all seven stages on main 0778be2f, which contains 2b8f14d8 ([run2.jsonl](../evidence/2184/run2.jsonl), [evidence README](../evidence/2184/README.md)):
  - Caller-bound preparation repeats with the same value. A wrong release key is refused.
  - A changed digest or a changed policy revision is refused before dispatch, and no launch is consumed.
  - Observe returns `verified-effective` with the named sandbox and scope-control queries.
  - Exact stdio peers: frontend, supervisor and native processes are bound; `initialize` is answered; no model turn runs.
  - After a frontend SIGKILL, release refuses ("protected descendant completion unproved; retain original slot") and relaunch refuses ("slot launch already consumed").
  - The sealed singleton certificate `taskq.native-completion/1` reports input closed. Reconcile completes cleanup, and a duplicate reconcile returns the same receipt.
  - Release reads back `released`, `occupied: false`. No `scope-run` or `codex app-server` process remains.
- A2 holds: the AssetQ Codex Workspace grant stays at revision 34; the candidate build was not installed; no model turn or paid call ran.
- The verdict is posted on #2151 ([PASS comment](https://github.com/taskqorg/taskq/issues/2151#issuecomment-6582876829)). It supersedes the earlier open-gate comment.

## Options

1. Accept the PM native run as the A6 proof. + Matches the §3 owner-account consumer boundary; + no grant change. - Needs a non-worker session for each rerun.
2. Add a worker-runnable native qualification path. + Workers could rerun it. - Weakens the §3 rule that workers cannot launch external app servers (R9).

## Verdict

Confirmed: native preparation, descendant completion and recovery pass on the Mac under existing Workspace authority (run 2).

## Recommendation

Option 1. Keep the qualification as a PM/owner run and rerun it only when the adapter's runtime path, permissions or native client change (R12). The interruption covered the frontend only; delegated remote/XPC effects stay out of scope, as the design says.
