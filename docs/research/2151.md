# Protected authority preparation and descendant completion

The source candidate adds independent preparation and a one-shot native scope to the existing protected adapter (R8/R9/R12/R13). It is not installed or natively qualified. The accepted AssetQ `05476e88c53f5232cc17f37bd664aad0ba103a79` composed PASS is reused unchanged. Merge-result CI and scoped PM qualification remain required (A6).

## Question

Can the adapter provide caller-bound expected authority before launch and reconcile the original native operation's descendants without replay, new grants or breaking legitimate native spawning/session/group APIs?

## Findings

### Native scope evidence

[Original failure traces](2151/observed.json) and the [owned instrument](2151/scope_probe.py) show detached `setsid`/`posix_spawn` descendants surviving root exit and disappearance of the original process group. Root/group absence does not prove completion. `NOTE_TRACK` returns `ENOTSUP (45)` on the observed Mac. [Pinned source excerpts](2151/source-evidence.json) also establish that CoreQ's exact-process identity/termination APIs are not descendant proof. The rejected [restriction fragment](2151/group-narrowing.sb) remains historical negative evidence; it is not adopted or rerun.

[Read-only coalition observations](2151/coalition-observed.json) and [pinned XNU source](2151/coalition-source-evidence.json) establish inherited resource-coalition membership across fork/exec/posix_spawn and same-lock started/exited counters. These SPI layouts require native qualification and fail closed on unsupported/error/mismatched observations. No PID census or process-group polling supplies completion.

The worker's original approved bootstrap returned 5; its own `job-creation` query returned denial (1, errno 0). That worker result remains **sandbox-blocked**, not PASS ([original redacted receipt](2151/launchd-observed.json)). It did not establish the unique cause of bootstrap's generic error. No worker retry or fallback ran.

[PM's authorized reconciliation](https://github.com/taskqorg/taskq/issues/2151#issuecomment-6564944210) supplies the missing isolated-scope experiment. Its retained private receipts were read back; the original root/leaf boot and coalition bindings agree. [Redacted host evidence](2151/authorized-host-observed.json) retains the attributable outcomes:

- The prepared Aqua job failed in the user domain with launchd session error 134; the exact prepared plist succeeded in the GUI domain (`bootstrap=0`, `kickstart=0`). This is a session-domain finding, separate from the worker's sandbox denial.
- The root had an isolated resource coalition and counters `started=3, exited=2`. After root exit, the exact detached `setsid` leaf remained live in that same coalition, with `started=5, exited=4`.
- Cooperative stop and bootout returned successfully. After the last member exited, resource accounting returned `-1/ESRCH (3)`, and exact-job print returned 113. Neither absence is classified as an empty-scope/completion proof.

This is evidence for an isolated inherited scope, not qualification of the new adapter, supervisor singleton certificate, cleanup recovery or Workspace enforcement. The worker performed no additional native-unit or app-server launch. Private host paths, identities, labels and release keys are not copied here.

### Implementation

`service app-server --action prepare` accepts only the existing schema and slot. Under the existing resource/grant lock, it authenticates the reserved slot and actual consumer incarnation, resolves current host revision/account and saves independent authority in that slot's host record. The private response includes canonical project, approver, native image/hash/home, adapter artifact, effective profile hash and caller/boot/host generation. It creates no job, slot or policy. Preparation is immutable for the operation; drift refuses rather than replacing it.

Launch requires the independently persisted preparation digest, revision and account. Fresh host authority and artifact equality are checked before intent and before native input. The original slot key, binding, secret-key hash and effect identity stay unchanged. An observed launch receipt cannot create preparation. Every consumed launch remains consumed after failure, cancellation or recovery.

A transient GUI-domain launchd job runs the trusted adapter supervisor, with no automatic start/restart, `LaunchOnlyOnce=true` and one explicit dispatch. It uses the existing resolved Workspace wrapper for the native client. The supervisor is host code, not a model runtime outside the boundary. Native `posix_spawn`, `setsid` and `setpgid` remain available. No second resolver, permission store, scheduler or ordinary worker path is introduced.

Private stdio sockets and job metadata live under the existing protected install. Peers authenticate kernel PID/creation identity, same OS account and the bound adapter image. The supervisor's boot/coalition identity must differ from the frontend and is saved/read back after acknowledged dispatch, before native spawn. The new control directory is protected by the generated profile and checked with existing-object kernel queries. Native stdout/stderr retain their separate streams.

After root exit, cancellation, caller loss or input error, the trusted supervisor closes native input and never creates further work. It retains its own coalition membership while waiting for inherited descendants. Only a successful same-boot kernel accounting read with that exact live supervisor as the sole remaining task can create a sealed certificate. Duplicate observations cannot reopen work; regressed/changed counters, missing scope, PID reuse, unsupported reads and uncertain ownership retain unknown occupancy.

Reconciliation reads only the original operation. Before cleanup it rechecks the sealed singleton counters, exact job program/argv/PID and adapter image. Cleanup intent precedes one bootout. A successful bootout acknowledgment is durable before exact supervisor-exit verification, so recovery after that acknowledgment does not repeat the command. A lost/uncertain acknowledgment never authorizes another bootout or generation. Host-verified completion/cleanup is additionally required by protected slot release; the consumer must still attest its entire turn and external effects, then read back the existing service acknowledgment. Legacy/unproved protected launches stay fenced. Verified later boot retains the existing §3 rule.

Coalition membership does not cover arbitrary remote work or delegation to launchd/XPC services. AssetQ retains orchestration, external-effect/tool completion, current image-tool capability and output acceptance (A8). AgentQ consumes these optional adapter actions; its ordinary runtime APIs remain unchanged.

### Regression evidence

The new missing-preparation regression first failed against the original intent writer: `missing independent preparation must refuse before launch intent`. After the preparation guard, the same regression passes. It uses invented in-memory authority and no slot CLI or native dispatch.

The deterministic models cover preparation/artifact/grant/caller/host drift, durable reload before/after intent, cancellation before identity, surviving detached work, reused supervisor PID, duplicate/reordered counters, original-operation no replay, cleanup acknowledgment gaps and immutable slot/effect binding. Existing resolver, grant-lock, artifact, sandbox-query and release-retention assertions are preserved. The old interruption fixture now supplies independent preparation before exercising its unchanged guards.

Review found that native stdout inherited the duplex input socket, letting native code read queued bytes through fd1 before the supervisor validated them (A2/R9). The output-descriptor regression reproduced that defect: the native descriptor read all 20 queued input bytes instead of refusing. Native stdout/stderr now inherit only write-only pipe ends. Trusted threads forward output and drain before completion certification and transport shutdown; the supervisor alone retains the input socket and its existing validation gate. The same regression passes: the native descriptor returns `-1/EBADF`, all queued input remains readable by the supervisor and output forwards to EOF. No native client or job is launched by this regression.

The contract lint also reproduced the CI failure at R8: 434 visible characters exceeded the 400-character source-line bound. Splitting the paragraph preserves its wording; the pinned lint then passes with a 394-character longest line and 291 total lines. Existing headroom warnings remain.

The local socket check exercises real kernel peer identity, bounded framing and preservation of bytes after the private request. The plist check protects the one-dispatch/no-restart surface. Neither starts a launchd job or native client, and neither qualifies the product lifecycle.

Existing filesystem fixtures are **sandbox-blocked** here when writing their invented `.codex/config.toml` (EPERM). The owner-slot fixture is blocked by the retained `TASKQ_ATTEMPT` refusal. ## Verdict

**Isolated coalition inheritance is confirmed by the retained PM fixture; product preparation/completion/recovery qualification is still unknown.** The source and deterministic guards implement A1-A5 with the existing authority and immutable slot protocol. The worker cannot claim A6 complete before merge-result CI and PM's exact-artifact native checks. A7's prohibited effects were not performed; A8's responsibility boundary is retained.

## Recommendation

Reuse the accepted composed boundary PASS; do not run a model/paid turn, crate replay, new grant, Full fallback, ordinary install or account/model/capacity change. Unknown native work or cleanup retains the original slot and private receipts.

Missing or incompatible support stays unknown. Do not infer completion from an absent coalition or repeat an uncertain dispatch.
