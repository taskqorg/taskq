## Findings and evidence

Run the owned, bounded instrument from this checkout:

```sh
python3 docs/research/2151/scope_probe.py
```

[Observed output](2151/observed.json) records the Mac worker run on Darwin 27.2.0/macOS 27.2. Its receipts deliberately omit private paths, process IDs, account data and release keys. [Instrument source](2151/scope_probe.py) contains assert-based failure checks and private-pipe teardown; no installed client or production process is controlled. Each wait has a 10-second deadline. These are process-fixture observations, not qualification of a protected native launch (R8/R12).

1. `EVFILT_PROC` accepts `NOTE_FORK|NOTE_EXIT`. Adding `NOTE_TRACK` returns `ENOTSUP (45)`. The retained XNU source explicitly rejects `NOTE_TRACK`, `NOTE_TRACKERR` and `NOTE_CHILD`; using FreeBSD child-tracking semantics on this Mac is invalid.
2. In both `setsid` and `posix_spawn(..., setsid=True)` traces, the root is reaped and its original process group is absent while the exact owned descendant remains alive in another group/session. Both descendants finish through their private controller pipe. These executable counterexamples refute root-only and unconstrained-group completion. They do not establish that a runtime fix passed.
3. Denying the `setsid` and `setpgid` syscalls alone is insufficient. In the retained XNU `posix_spawn` source, `POSIX_SPAWN_SETPGROUP` calls `setpgid` internally, and `POSIX_SPAWN_SETSID` calls `setsid_internal`. Those calls do not enter either syscall. The instrument proves ordinary spawn detachment; the combined deny-profile bypass remains source evidence, not a qualified native observation.
4. CoreQ's locked `v0.18.0` source is `e84761cdab43723b871a42b3021e9c39afcd9484`. Its identity/termination APIs are suitable for PID-reuse fencing and exact cancellation. Its contract explicitly says identity is not descendant or external-effect proof. Bounded exchange/reaper cleanup owns the direct child and writer; it does not supply a recoverable Mac descendant scope. Checked CoreQ main `55ec4176372b7832790c6d6e59d1b149b79e4dfb` has the same process source blob and no separate scope/process module in its complete tree. No dependency pin changed.
5. Kernel coalitions provide a stronger lifecycle object, but the reviewed XNU coalition syscall refuses callers outside a privileged coalition. No coalition create, entitlement request, privileged helper, LaunchAgent submission or authority change was attempted. An existing TaskQ process group must not be represented as a private kernel coalition.
6. Inherited Seatbelt markers plus a process census are an investigation lead, not completion proof. A PID census is not an immutable birth/exit journal: the reviewed `proc_iterate` first collects PIDs, unlocks, then finds them for callbacks. Fork, exit and PID reuse can race the later reads. A same-user operation can also match another sandbox's deny rule. No marker scanner, global process killer or polling-based release is proposed for adoption.
7. Applying the candidate's new narrowing to an owned fixture returns `sandbox_init: -1`, `Operation not permitted` inside this worker. Its three enforcement checks are **sandbox-blocked**, not PASS. No retry with different permissions, attempt stripping or slot refusal bypass occurred. The cause is not attributed to TCC.

[Source evidence](2151/source-evidence.json) retains exact excerpts, line positions, Git blob identities and immutable retrieval URLs for CoreQ, XNU, Rust and CPython. The XNU publication is source evidence, not a claim that its revision exactly matches this host's running kernel. Third-party [kstack analysis](https://github.com/kstackhq/kstack/blob/2f3c8ca83da0ceac0b0df69ff77f664eff45e574/docs/adr/2026-09-28-a-macos-run-keeps-its-group-by-refusing-setsid.md) independently identifies the spawn-attribute escape; it is supporting analysis, not authority or qualification.

The earlier filtered slot-unit attempt stopped at `a worker cannot reserve or release external slots`. That is the retained authority guard, not reproduction of a slot implementation defect. No before/after fix PASS is claimed.

## Concrete candidate and effects

[Proposed profile fragment](2151/group-narrowing.sb) adds only these denials to the existing resolved protected Workspace profile:

```scheme
(deny syscall-unix (syscall-number SYS_setsid SYS_setpgid) (with errno 1))
(deny syscall-unix (syscall-number SYS_posix_spawn) (with errno 78))
```

This is a review candidate, not an active contract or drop-in replacement profile. It grants nothing. It closes the three reviewed group/session escape paths by refusing the corresponding native APIs; ordinary workers and runtime paths would retain their current profiles. It does **not** promise compatible native tools. CPython's spawn branch propagates the error. The reviewed Rust Mac spawn branch also propagates a nonzero return; its Linux pidfd `ENOSYS` fallback cannot be assumed on Mac. No automatic fork fallback, executable shim, environment workaround or tool substitution is part of this candidate.

If the owner accepts that product restriction, the implementation candidate is:

1. Prepare through the existing host resolver and operation store, bound to the original slot, real consumer incarnation, policy/account, artifact/home and resulting profile hash. Launch independently compares that preparation and revalidates current authority before input (A1/A2).
2. Before entering native code, establish an operation-owned process group and verify the added denials under the required outer Workspace profile. Persist the original group anchor, native incarnation, boot and one consumed launch intent. A failed enforcement read or uncertain spawn never opens input or permits a second launch.
3. Seal further input/launches before completing the operation. Only proven enforced membership, a sealed launch boundary and conclusive end of the original group can form completion evidence. Root absence, a terminal native event, an empty unbound PID scan or supervisor loss cannot substitute for those prerequisites. Group-ID reuse, missing authority or unknown observations retain occupancy; cancellation may use CoreQ's exact-incarnation termination, never an unchecked recycled group ID.
4. Reconcile only the original immutable operation; persist completion before permitting its original authenticated slot release and require host acknowledgment. Crashes, changed policy and duplicate observations cannot reopen input or relaunch. The same resource store owns recovery; no extra resolver, grant store or scheduler appears.

This is not yet an executable proof of steps 1-4. A full supported-scope implementation and A5 models still have to protect intent/spawn gaps, interrupted anchors, PID/group reuse, surviving descendants, duplicate/reordered observations and original-slot acknowledgment. In particular, loss of an enforceable membership or launch-sealing fact must remain unknown, even if all observed processes vanished.

**External effects:** none from publishing this report/candidate. Adoption would narrow only the optional protected app-server's process APIs and may make legitimate native command tools fail. It would not create grants, widen Workspace, change model/account/capacity, install a helper or alter ordinary workers.

**Rollback:** before admission, discard the candidate source/profile fragment; no host restoration is needed. After any later approved adoption, stop new admission first and preserve every original operation/profile/native identity and occupied slot until verified completion. Rolling back source must never relaunch uncertain input, erase ownership or release unknown work.

**Qualification:** after a reviewed immutable implementation and green merge-result CI, PM runs only disposable process-scope fixtures under the existing Mac Workspace authority: direct syscall denial, spawn-attribute denial, inherited enforcement through fork/exec, successful permitted command behavior, surviving descendants, supervisor/caller interruption, same-operation recovery and acknowledged original-slot release. Do not replay the composed AssetQ boundary, a model/paid turn or its accepted crate. Worker fixtures and source inspection cannot qualify these paths.

## Verdict

**Inconclusive for the requested useful native scope.** Unconstrained process groups and `NOTE_TRACK` are refuted on the investigated boundary. The stricter profile is a concrete product restriction, not a compatible proven replacement. Its enforcement is sandbox-blocked in this worker. No supported mechanism preserving the current native tool surface has been established.

## Recommendation

Preserve the current tool surface and unknown fencing. Do not silently adopt the syscall restrictions. The owner must decide whether the optional protected path may refuse these native APIs before that candidate can be implemented and qualified. If tool compatibility must remain, retain the A3/A4 blocker rather than claiming boot-only or polling completion.

AgentQ #199 waits on this boundary, so the worker returns this concrete decision through `ask`, not `result` or a claim that #2151 is delivered (§7, R12/R13).
