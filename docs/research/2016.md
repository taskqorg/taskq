# GitHub comment collapse, non-branch evidence ref and GitLab note options

## Question

[#1980](https://github.com/taskqorg/taskq/issues/1980) recommends a summary comment plus GitHub's native collapse of ended service entries, and a non-branch ref for evidence files. It left three unknowns that block adoption under R12:

1. Does collapsing a taskq entry with `minimizeComment` change what `fold` reads?
2. Does a file under a non-branch ref open by its commit-pinned raw URL in a public and a private repository?
3. Which note collapse, resolve and internal-note options does a GitLab board offer, and does a note edit add a system note or change `updated_at`?

**Status.** A1 and A2 are answered below. A3 waits for [#2030](https://github.com/taskqorg/taskq/issues/2030) on the Mac host, because the Windows host has no GitLab access.

Raw readbacks: [2016-readbacks.json](2016-readbacks.json).

## Findings

### A1. `minimizeComment` changes `updated_at`, so `fold` drops the entry

Probe: a private scratch issue, [alexkirs/taskq-native-qualification-20261011-p1#14](https://github.com/alexkirs/taskq-native-qualification-20261011-p1/issues/14), without the `taskq` label. The owner posted five comments: `taskq: hold`, `taskq: start`, `taskq: spawn worker claude:probe-2016 win`, one human note and `taskq: result <sha> attempt <spawn id>`. Then the owner minimized `hold` as `RESOLVED` and `start` and `spawn` as `OUTDATED` through GraphQL.

REST readback of `GET /issues/14/comments` (times UTC, 2026-10-31):

| Comment | Entry | `created_at` | `updated_at` before | `updated_at` after minimize | REST `minimized` after |
|---|---|---|---|---|---|
| 6539529053 | `hold` | 05:24:08 | 05:24:08 | 05:24:47 | `{"reason":"resolved"}` |
| 6539529455 | `start` | 05:24:11 | 05:24:11 | 05:24:49 | `{"reason":"outdated"}` |
| 6539529893 | `spawn` | 05:24:14 | 05:24:14 | 05:24:50 | `{"reason":"outdated"}` |
| 6539530314 | human note | 05:24:17 | 05:24:17 | 05:24:17 | `null` |
| 6539531783 | `result` | 05:24:28 | 05:24:28 | 05:24:28 | `null` |

- Body and comment order are unchanged: all five bodies are byte-identical, ids keep their order, `author_association` stays `OWNER`.
- `updated_at` moves to the minimize time on every minimized comment. The REST comment also gains a `minimized` field.
- GraphQL `lastEditedAt` stays `null` on minimized comments; GraphQL `updatedAt` moves like REST `updated_at`.
- The issue's own `updated_at` moves to the last minimize (05:24:28 to 05:24:49).
- `unminimizeComment` does not restore the old value: it moves `updated_at` again (spawn: 05:25:13), and REST `minimized` returns to `null`. The unminimized comment then looks edited to a REST reader, with nothing that tells it apart from a real edit.
- A real body edit (REST `PATCH` of the human note at 05:25:14) sets GraphQL `lastEditedAt` to the edit time. So `lastEditedAt` separates edits from collapses; REST has no equivalent field.

Fold, with the current GitHub adapter rule `edited = updated_at != created_at` ([src/board/github.rs](../../src/board/github.rs), `comments`) and `core::fold`, run on the three readbacks:

| Snapshot | Edited entries | Fold |
|---|---|---|
| before | none | `review`, result `1111…1111` |
| after minimize | `hold`, `start`, `spawn` | `ready`, no result |
| after unminimize and edit | `hold`, `start`, `spawn`, human note | `ready`, no result |

The change is named: under today's contract (§ 2: "An edited comment (`updated_at` after `created_at`) … is ignored") a collapsed entry is an ignored entry. Collapsing the entries of an ended attempt removes them from `fold`; here the task fell from `review` back to `ready` and lost its result. Unminimize does not repair it.

### A2. A non-branch ref serves commit-pinned files; private repositories need authentication

Probe: one orphan commit `d5773f3003c3e1232cf61d3b5c57952096937f85` with a text file and an 8×8 PNG, pushed as `refs/taskq/probe-2016` to the public [taskqorg/taskq](https://github.com/taskqorg/taskq) and the private scratch repository. Both pushes succeeded; the taskq rulesets (`live`, `main up to date`) target branches only and did not apply. `git ls-remote` lists the ref on both.

| URL form (commit SHA, not ref) | Public, anonymous | Private, anonymous | Private, API token |
|---|---|---|---|
| `raw.githubusercontent.com/<repo>/<sha>/<file>` | 200, `image/png` / `text/plain` | 404 | 200 (`Authorization: token` header) |
| `github.com/<repo>/raw/<sha>/<file>` | 200 after redirect to raw | 404 | 404 (web route ignores the header) |
| `github.com/<repo>/blob/<sha>/<file>` | 200, HTML page | 404 | not tried |
| `GET /repos/<repo>/contents/<file>?ref=<sha>` | 200 | not tried | 200 |

- Public: [probe-2016.png](https://raw.githubusercontent.com/taskqorg/taskq/d5773f3003c3e1232cf61d3b5c57952096937f85/probe-2016.png) opens in one click without login, exactly like a file on a branch.
- Private: anonymous access fails for the non-branch ref and equally for `main/.gitignore` (control). This is the private-repository rule, not a ref effect. The API path and the token-authenticated raw host work. A signed-in member's browser click on `github.com/<repo>/raw/<sha>/…` was **not** tested (no browser session on this host); it stays unknown.
- Clones: a default `git clone` of the private repository has fetch refspec `+refs/heads/*:refs/remotes/origin/*` and does not contain the probe commit (`git cat-file -e` fails); `git fetch origin refs/taskq/probe-2016` gets it. A partial clone (`--filter=blob:none`) appears to contain it only because the lazy fetch downloads it on demand. Mirror clones were not tested.
- Not tested: whether GitHub garbage-collects a commit after its non-branch ref is deleted, and how long such a commit URL keeps serving.
