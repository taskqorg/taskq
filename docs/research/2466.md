## Findings with evidence

### A1 checkpoint: exact refusal and repetition

The binding §7 [publication routes](../design/agent-behavior.md#publication-routes) says: “No commit (research, SHA on `main`): check ancestry, close.” It does not provide an off-main evidence-only outcome. The existing result SHA serves both as the identity under review and as the source to publish. R12 requires keeping those claims distinct when publication is unknown.

The implementation explains the receipts:

1. `src/board/github.rs::defer_publication` defers every `pr` close. `src/dispatch.rs::close_body` saves the reviewer's verdict as `publish` before the service reconciles it (§2.15).
2. `GitHub::try_publish` resolves eligible foreign publication PRs, then compares `main...<result>`. `publish_in` returns `Done("<sha> already on main")` only for `identical` or `behind` (except a named foreign merge commit, which must qualify its merge CI).
3. Otherwise the `pr` route reads main rules and open `taskq-2462` PRs to main. With none, it reads closed task PRs, tries exact-head/merge identity or patch reconciliation, then returns `Publish::Blocked` when none are merged. This is the exact refusal string in both receipts.
4. `dispatch::resume_publication` translates `Blocked` into `publication-blocked`. `core::step` retains the result and saved publication, sets Ask, and resumes Review on an accepted answer (§2.16/20). The answer text is a durable note; it is not an adapter route selector.
5. The service therefore repeats the same publication lookup. It does not rerun qualification, spawn a new reviewer or turn an answer into merge evidence.

The missing PR is a consequence of the result being routed as source publication. It is not a transient CI failure, a missing native grant or a reason to replay the probes. A generic retry cannot meet #2462 A4. The “later, then close” text in its saved verdict is an unsupported workaround for this task: closing Later/Failed is an owner act (§2/§7), and #2466 expressly forbids that route.

### A2 checkpoint: supported boundary and precise change required

The supported no-commit route today requires the result SHA already on main. An ancestry read returning `identical` or `behind` reaches `Done` without a PR or merge; this is source inspection, not a live demonstration. It cannot accept #2462's recorded off-main candidate as-is. No supported command was found that preserves that result identity while selecting an off-main evidence-only close.

Do not substitute a convenient main SHA for the tested candidate, create an empty task PR, associate an unrelated PR, change delivery policy, or weaken merge evidence. Those actions would either misstate identity, violate A4 or change authority (R9/R12). Squashing #2427 also does not establish that its original candidate SHA is an ancestor of main. Any later ancestry claim needs a fresh board read.

A durable remedy needs an owner-approved §7 distinction between an evidence outcome and source publication (R13). Proposed behavior, not an adopted rule:

- A board-owned, explicitly authorized evidence outcome records the exact candidate repository/SHA, immutable evidence attachment identity and accepted reviewer verdict. It says that this task delivers no source delta and does not publish the candidate. A label, `Changed: none`, worker prose or arbitrary answer alone never selects it.
- Owner authorization binds this task, outcome revision and exact candidate/evidence identity. A task with source work cannot infer this authorization from the absence of a PR. Unknown scope or task-owned source delta refuses; the implementation must establish no source delta against the attempt's recorded baseline, not compare the tested candidate with main.
- Keep the existing owner gate before any completion. A required/stale gate or changed evidence identity requires fresh approval. Evidence authorization cannot approve a separate source result or #2427.
- Preserve the accepted result/evidence identity and all qualification limitations. Record an explicit evidence-only receipt, never `merged`, `already on main` or a fabricated CI success. #2427's source publication still needs its own merge-result CI.
- Use the existing close/publish reconciliation, revision/op-id fencing and close readback. Unknown prior write reconciles the same identity; it never reruns input or launches a runtime.

Implementation work would touch the owning §7 contract/detail first, the §2 model only if new durable entry semantics are chosen, result parsing/identity (`core.rs`), guarded closure and pending reconciliation (`dispatch.rs`), board evidence/readback, and accepted-result/readiness/report projections. The current `Board::publish` interface takes source SHA and publication mode, not an evidence outcome: the new path should be validated before entering that source adapter, in both initial close and pending publication. Existing pending verdicts such as #2462 need explicit revision-bound reconciliation, not a text heuristic. §8 reader compatibility must be resolved before writing any new semantics.

```python
# Investigation model only; no TaskQ imports, network or runtime calls.
from itertools import product

def decide(kind, scope, review, binding, no_delta, gate, prior):
    # Each predicate is verified True, verified False, or unknown (None).
    if prior is True:
        return 'existing receipt', ()
    if prior is None:
        return 'reconcile', ()
    if kind != 'evidence':
        return 'normal publication', ()
    if all(x is True for x in (scope, review, binding, no_delta, gate)):
        return 'evidence close', ('board close',)
    return 'refuse', ()

count = 0
for kind in ('evidence', 'code', 'unknown'):
    for values in product((True, False, None), repeat=6):
        outcome, effects = decide(kind, *values)
        scope, review, binding, no_delta, gate, prior = values
        if outcome == 'evidence close':
            assert kind == 'evidence'
            assert all(v is True for v in values[:5])
            assert prior is False
        if kind != 'evidence':
            assert outcome != 'evidence close'
        if gate is not True or no_delta is not True:
            assert outcome != 'evidence close'
        if prior is not False:
            assert effects == ()
        assert set(effects) <= {'board close'}  # no merge, native launch or input
        count += 1
assert decide('evidence', True, True, True, True, True, False)[0] == 'evidence close'
print(f'{count} proposal cases passed; production route unimplemented')
```
