## Options

1. **Integrate scoped deltas into existing components.** Pros: preserves shipped native adapters, newer decisions and receipts; one coherent UI with existing task ownership. Cons: requires careful three-gate regression and native proof rather than accepting mock screenshots.
2. **Replace current files with the older snapshot or ship its string-transform adapters.** Pros: superficially reproduces the demo quickly. Cons: violates A3/A4, restores old caps/overflow/pin behavior and forks rendering/state authority. Rejected by the task; no permission to choose it.
3. **Accept the prototype or closed tasks as final proof.** Pros: avoids new native measurement. Cons: fails R12/A7 and leaves live input/history/OS behavior unknown. Rejected by the task.

## Recommendation

Use option 1 and the existing task chain. Preserve current-main improvements and the explicit owner selections. Treat UI30 as a target until the implementation slices and exact-source native packets pass; return one integrated result to the owner for independent review. No new tasks are needed.
