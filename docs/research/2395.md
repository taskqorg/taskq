# Immutable batch replay pilot

## Question

Can three to five independent accepted TaskQ deltas be replayed in private Git,
with immutable evidence and failure localization, before considering production
batching? Source request and acceptance: [#2395](https://github.com/taskqorg/taskq/issues/2395).

## Plan and rollback (written before implementation)

R8/R12/R13: this is an explicitly isolated, offline experiment. It changes no
production admission, publication, release, runtime policy, queue capacity or
installed runtime. Feature PR checks and merge-result gates remain required.
The pilot consumes #2391's authoritative accepted-result projection; it never
parses lifecycle comments or treats the latest matching comment as acceptance.
Missing source proof refuses qualification and is recorded as unknown.

1. Freeze inputs by digest: producer revision/export, accepted attempt/result,
   repository/PR, result SHA, original PR base (observed or null), original merge
   parent, merged delta, exact CI run/attempt/SHA, and current reviewed source.
   Preserve historical unknowns; experimental base/head are distinct fields.
   Accepted-result identity is required independently of advisory source-ready.
   Prove integration coverage by applying the exact result delta from its frozen
   Git ancestor to the original merge-parent tree in private Git; require the
   observed merged tree exactly. A derived Git ancestor never proves a historical
   PR base. Conflicts or extra changes refuse rather than borrowing source-ready.
2. In a new private temporary Git repository without remotes, import only the
   frozen source. Reverse the three verified merge deltas, then replay those
   exact binary patches in all six orders. Reject dependencies, moved inputs,
   overlapping/conflicting changes, mismatched result deltas or extra changes.
   Every order must reproduce the frozen source tree exactly.
3. Run the complete unchanged canonical gate (`python3 scripts/check.py --full`)
   on the frozen replay head with existing early pinned lint. One initial gate,
   900-second canonical budget, no retry-to-green. Keep the host, tools, command,
   head, elapsed time, exit status and log digest in content-addressed receipts.
4. If the original gate fails, check deterministic subsets, using an exact-input
   cache. Report minimal failing sets, interactions and unknowns; never remove
   members or upgrade the original outcome using diagnostics. Synthetic fixtures
   exercise refusal and diagnostic behavior separately from real evidence.
   A subset with changed check definitions is non-comparable: keep its observed
   outcome but report causal clearance as unknown. Conservatively fingerprint
   source files too, because Rust embeds regression checks beside implementation.
   Never overlay production checks or remove members to obtain a passing batch.
   Replay inputs are frozen from the reviewed source, including later reviewed
   hunks. A whole-file historical blob mismatch alone does not mean those frozen
   inputs moved. Exact Git reversal must match the verified delta's postimage
   context; freeze its resulting before/after blobs, then enforce those identities
   in every replay order. Conflicting hunks still refuse, and all orders must
   reproduce the entire reviewed tree, preserving unrelated later changes.
5. The full-matrix handoff retains the reviewed source commit as an explicit
   bundle prerequisite. Prepare the private replay head and a sanitized manifest
   as a Git bundle; preparation remains pending, never PASS. The operator verifies
   exact tree identity, publishes a unique non-release proof ref and returns the
   unchanged `tests.yml` full OS matrix's exact run, attempt, SHA and jobs. The
   pilot itself never publishes. Once that proof is verified, do not duplicate
   the local replay Windows gate; the feature-candidate checks remain required.

Rollback: stop only the pilot's own command, preserve its immutable receipts and
logs, and discard its private temporary repository. There is no production
rollback, queue write, service restart, release or installation to undo. Existing
different receipt bytes refuse overwrite. Receipts are local evidence digests,
never TaskQ events or acceptance authority. No credentials or private host paths
belong in committed evidence.

### Tool and synthetic protection

`scripts/batch-replay.py` reads a frozen manifest, imports only frozen tree
objects into private Git with no remotes, proves source coverage, reverses verified
deltas and applies all permutations. Its gate is the unchanged
`python3 scripts/check.py --full`; its experimental base commit is the gate
head's parent. It records inputs, patches, tool identity, host, command, frozen
head/tree, outcome, timing and log digests. Exact-input cached command receipts
are checked against their content and log hashes before reuse. A corrupt existing
receipt is never overwritten. Failed original batches retain every member and
their failed outcome while deterministic subsets, including the empty baseline,
identify failures, interactions and unknowns.

Run the focused synthetic suite with `python3 scripts/batch-replay.test.py`.
It is also wired into `scripts/check.py`, after the existing early pinned lint.
Synthetic gate callbacks are explicitly labelled and cannot qualify real tasks.
The suite covers three-to-five-member validation, six actual Git replay orders,
missing and stale source proof, moved heads/inputs, tampering, dependency refusal,
overlaps, patch conflicts, hidden changes, exact CI identity, historical unknowns,
failed and interacting gates, receipt replay/cache reuse and corrupt logs.
The disappearing-check fixture also requires a subset's observed PASS to read
unknown when removing a member removes its regression assertion. Check-input
fingerprints include Rust sources conservatively; a changed fingerprint cannot
prove causal clearance. Gate receipts/cache keys bind the actual check-input
identity, frozen source, pilot tool digest, tool versions and environment digest.

The canonical hook initially failed `scripts/check.test.py` at its five-call
expectation: the new hook correctly made six calls. The updated check passes
with six and explicitly requires exactly one replay-test invocation only after
successful lint. The lint-first, once-only and failure-before-tests protection is
retained (R8/R12); no contract assertion was weakened.

Private invocation, after the authoritative producer export exists:

```sh
python3 scripts/batch-replay.py manifest.json --source /exact/source/repo --receipts /private/pilot/receipts
python3 scripts/batch-replay.py manifest.json --source /exact/source/repo --receipts /private/pilot/receipts --prepare-bundle
```

The manifest format is exercised by the synthetic fixture builder in
`scripts/batch-replay.test.py`. It carries `schema: 1`, `synthetic`, repository,
immutable producer revision/executable digest and frozen source head, and three to five members.
Each member freezes the #2391 export and canonical JSON digest, expected
task/attempt/result-entry/result SHA, publication mapping, dependency issue body,
derived source-delta base, merged-delta digest and exact CI API observation.
The `accepted_result_state: proven` projection comes from the frozen #2391
producer above, not an installed-runtime claim. Original PR base, derived source-delta base,
historical merge parent and experimental replay base retain distinct meanings.

Keep raw receipts and logs private: commands can contain host paths. Publish a
sanitized summary with their digests, preserving the exact SHAs and outcomes.
The temporary repository is removed after its command finishes; receipts and
logs survive separately. A receipt digest is never a TaskQ lifecycle event.
